## Baseline روش پایدار ۰۷:۴۰

فراخوانی یک‌مرحله‌ای `FindAll(Descendants)` در Provider فعلی UI Automation
متوقف می‌شد. سه Client قدیمیِ فقط‌خواندنیِ گیرکرده بسته شدند؛ Process وارانگار
دست‌نخورده و پاسخ‌گو ماند. Extractor به پیمایش breadth-first با
`TreeScope.Children` و سقف ایمنی ۵۰۰۰ Element تغییر کرد؛ هیچ Invoke یا Input
اضافه نشد.

این روش ۸۳ Control و ۱۹ Label مجاز را می‌بیند، در حالی که روش قبلی ۷۶/۱۸ بود.
مقایسه ۰۷:۴۰ با ۰۵:۴۵ با وضعیت `OBSERVATION_METHOD_CHANGED` چهار بخش
`source`، `summary`، `windows` و
`safe_named_controls` را Changed اعلام می‌کند؛ `safety` و درخت Win32 بدون
تغییرند. تکرار فوری روش جدید هر شش بخش را بدون تغییر بازگرداند. این نتیجه
به‌علت تغییر روش مشاهده، شاهد Release drift محسوب
نمی‌شود. Snapshot نهایی ۰۹:۰۰ برای تشخیص Drift فقط با Baseline ۰۷:۴۰ و همان
Extractor مقایسه می‌شود.

Probe موقت ساعت ۰۸:۰۰ با همین Baseline هر شش بخش را `UNCHANGED` و وضعیت را
`NO_SEMANTIC_UI_DRIFT` برگرداند: یک پنجره، ۸۳ Control و ۱۹ Label مجاز. این Probe
صرفاً کنترل پایداری روش بود و وارد Bundle نهایی نمی‌شود.
