# 1. Purpose

NeginAI Token Architecture defines the technical design language shared between:

- Brand Identity
- Figma Variables
- Design System
- Frontend Components
- Runtime UI

Tokens are the bridge between design and implementation.

Architecture:

Brand Rules

↓

Foundation Tokens

↓

Semantic Tokens

↓

Component Tokens

↓

Application UI

---

# 2. Token Principles

## Single Source of Truth

No visual value should exist without a token.

Avoid:

- Hardcoded colors
- Random spacing
- Independent component styling

---

## Semantic Meaning

Components should consume meaning, not raw values.

Example:

Wrong:

```css
color: #4fd1ff;
```

Correct:

```css
color: var(--ng-action-primary);
```

---

## Theme Ready

Token architecture must support:

- Light mode
- Dark mode
- Future branding changes

---

# 3. Token Layers

NeginAI Tokens have four layers:

---

## Layer 1 — Foundation Tokens

Raw design values.

Examples:

- Colors
- Typography
- Spacing
- Radius
- Shadow
- Motion

---

## Layer 2 — Semantic Tokens

Business meaning.

Examples:

- Primary Action
- AI Surface
- Warning State
- Critical Alert
- Workspace Background

---

## Layer 3 — Component Tokens

Component specific values.

Examples:

- Button
- Card
- Navigation
- Input
- AI Panel

---

## Layer 4 — Experience Tokens

Large experience patterns.

Examples:

- Dashboard Workspace
- AI Assistant Panel
- Operational Card
- Mobile Dock

---

# 5. Typography Tokens

Font system must support:

- Persian RTL
- English
- Enterprise readability
- Dense information environments


Typography scale:

```
display-xl

display-lg

heading-xl

heading-lg

heading-md

body-lg

body-md

body-sm

caption
```

Each typography token contains:

- font family
- size
- weight
- line height
- letter spacing

# 15. Governance Rules

Every new token requires:

- Clear purpose
- Usage example
- Component mapping
- Figma variable definition

Avoid:

- Duplicate tokens
- One-off values
- Component specific hacks
