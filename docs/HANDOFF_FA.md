## هدف اصلی

ساخت دستیار هوش مصنوعی فارسی شرکت نگین پخش برای خواندن امن دیتابیس SQL Server
`NeginPakhsh`، شناخت ساختار و اصطلاحات شرکت و پاسخ‌گویی به سؤال‌های مدیریتی و
فروش. دیتابیس باید همیشه فقط‌خواندنی باقی بماند.

## تصمیم‌های اصلی که در گفت‌وگو گرفته شد

1. ابتدا قرار بود پروژه مستقیماً با OpenAI API کار کند.
2. سپس معماری به یک درگاه امن برای Custom GPT Actions تغییر کرد تا با حساب
   ChatGPT Plus کار کند و OpenAI API در آن بخش استفاده نشود.
3. نسخه Custom GPT ساخته و به API متصل شد و باید همچنان حفظ شود.
4. بعداً حساب OpenAI API شارژ شد و تصمیم گرفتیم علاوه بر Custom GPT، یک دستیار
   مستقل برای وب، ویندوز و در ادامه موبایل داشته باشیم.
5. نسخه مستقل اکنون از OpenAI API و Agents SDK استفاده می‌کند؛ کلید API فقط
   روی سرور در `.env` نگهداری می‌شود و به مرورگر فرستاده نمی‌شود.
6. معیار «فروش» در صورت مبهم بودن باید ابتدا مشخص شود: حواله، فاکتور یا هر دو.
7. فروش خالص فقط طبق تعریف تأییدشده شرکت و با کسر برگشتی محاسبه شود.
8. برند و تولیدکننده دو مفهوم متفاوت هستند و نباید جای یکدیگر استفاده شوند.
9. برندها و تولیدکنندگان باید خودکار از نرم‌افزار اصلی همگام شوند و نیاز به
   تعریف دستی تک‌تک آن‌ها نباشد.
10. فعلاً ساخت نرم‌افزار جامع جایگزین ورانگر متوقف شد تا خود دستیار کامل شود.

- فایل اکشن: `openapi-action.yaml`
- API عمومی مورد استفاده: `https://ai.neginpakhsh.com`
- احراز هویت اکشن با Header و کلید داخلی انجام می‌شود.
- Custom GPT ساخته شده و لینک اشتراک آن در حساب سازنده موجود است.
- این بخش وابسته به OpenAI API نیست و از قابلیت Actions حساب ChatGPT استفاده
  می‌کند.

### ۲. دستیار مستقل وب و ویندوز

- رابط محلی: `http://127.0.0.1:8000/assistant`
- رابط عمومی مورد نظر: `https://ai.neginpakhsh.com/assistant`
- فایل اجرایی ویندوز: `NeginAI-Assistant.exe`
- رابط واکنش‌گرا و PWA است و از مرورگر موبایل قابل Add to Home Screen است.
- مدل پیش‌فرض فعلی: `gpt-5.6-sol`
- سطح استدلال فعلی: `medium`
- موتور فعلی: OpenAI Agents SDK، نه تولید SQL تک‌مرحله‌ای.

## معماری عامل هوشمند فعلی

فایل اصلی عامل:

```text
app/chat_service.py
```

عامل به‌صورت چندمرحله‌ای می‌تواند:

- تعریف‌ها و قوانین کسب‌وکار را جست‌وجو کند.
- برند و تولیدکننده را با شناسه و رابطه صحیح تشخیص دهد.
- نام Table، View و ستون‌ها را در Snapshot ساختار جست‌وجو کند.
- جزئیات کامل یک Object، کلید اصلی و روابط آن را بگیرد.
- فقط یک `SELECT` یا `WITH...SELECT` را اجرا کند.
- در صورت خطای SQL، خطا را بررسی، ساختار را دوباره جست‌وجو و SQL را اصلاح کند.
- نتیجه نهایی، جدول، SQL اجراشده و منابع داده را به رابط برگرداند.

ابزار اجرای SQL همچنان از `sqlglot` و کنترل‌های `app/sql_guard.py` عبور می‌کند.
عملیات زیر ممنوع‌اند:

```text
INSERT, UPDATE, DELETE, MERGE, DROP, ALTER, CREATE,
TRUNCATE, EXEC, EXECUTE, SELECT INTO, multiple statements
```

اتصال SQL نیز با `ApplicationIntent=ReadOnly` انجام می‌شود و کاربر SQL باید در
خود SQL Server فقط مجوز خواندن داشته باشد.

- ذخیره تاریخچه مکالمه
- نمایش پاسخ، جدول، منابع و SQL
- Custom GPT Action schema
- فایل اجرایی ویندوز و PWA موبایل
- دامنه و HTTPS با Caddy/NAT برای دسترسی بیرونی

## آخرین تغییر مهم

پاسخ‌گویی مستقل قبلاً دو مرحله ثابت داشت: تولید SQL و سپس ساخت پاسخ. این روش در
سؤال‌های واقعی، مخصوصاً هنگام پیدا نکردن View یا ستون، زود تسلیم می‌شد.

اکنون `app/chat_service.py` به یک Agent چندمرحله‌ای تبدیل شده است. عامل می‌تواند
چند ابزار را پشت سر هم صدا بزند و SQL ناموفق را اصلاح کند. سناریوی واقعی زیر
با موفقیت آزمایش شد:

```text
کاربر: فروش ۱۲ مرداد را اعلام کن
دستیار: فروش بر اساس حواله، فاکتور یا هر دو؟
کاربر: هر دو
```

عامل سپس فروش و برگشتی را از Viewهای تأییدشده خواند و فروش خالص را برگرداند.
مقادیر واقعی فروش در این سند درج نشده‌اند.

## نکات شبکه

- برای دسترسی عمومی، روی MikroTik قوانین NAT پورت‌های ۸۰ و ۴۴۳ به ماشین سرویس
  تنظیم شد.
- زیردامنه `ai.neginpakhsh.com` استفاده شد تا سایت اصلی شرکت تغییر نکند.
- Caddy برای HTTPS و Reverse Proxy استفاده می‌شود.
- تست دامنه عمومی از داخل همان شبکه ممکن است به‌دلیل Hairpin NAT شکست بخورد؛
  بررسی واقعی باید با اینترنت موبایل خارج از Wi-Fi انجام شود.
- دسترسی خارجی در موبایل مشاهده شده، ولی گاهی خطای `Load failed` گزارش شده بود؛
  پایداری Caddy، NAT، Windows Firewall و اجرای دائم سرویس هنوز باید مانیتور شود.

## امنیت و اطلاعات محرمانه

- هیچ مقدار واقعی از SQL password، OpenAI API key، کلید داخلی، رمز روتر یا حساب
  دامنه در این فایل نوشته نشده است.
- `.env` در `.gitignore` قرار دارد و نباید ارسال یا Commit شود.
- در گفت‌وگوی قبلی چند رمز و کلید واقعی نمایش داده شده‌اند. بنابراین در اولین
  فرصت باید همه آن موارد Rotate شوند: رمز SQL، کلید داخلی Action، کلید/توکن
  سرویس تونل قدیمی، رمز MikroTik و هر کلید OpenAI که احتمال افشا دارد.
- بعد از تعویض، فقط `.env` روی سرور به‌روزرسانی شود و مقدارها در چت فرستاده نشوند.

## کارهای بعدی پیشنهادی به ترتیب

1. رابط را با `Ctrl+F5` تازه‌سازی و چند سؤال واقعی فروش را آزمایش کنید.
2. سناریوهای ثابت ارزیابی بسازید: فروش حواله، فروش فاکتور، هر دو، برگشتی، برند،
   تولیدکننده، فروشنده، مشتری و بازاریاب.
3. برای تعریف‌های مهم شرکت Approved SQL یا View گزارش تأییدشده ثبت کنید.
4. پایداری دسترسی عمومی را حداقل چند ساعت مانیتور و Caddy را به Windows Service
   تبدیل کنید.
5. ورود آزمایشی فعلی را با مدیریت کاربران، رمز Hashشده، نقش‌ها و محدودیت شعبه
   جایگزین کنید.
6. کلیدهای افشاشده را Rotate کنید.
7. بعد از پایدار شدن نسخه وب، بسته موبایل واقعی (Android/iOS) ساخته شود؛ فعلاً
   PWA قابل استفاده است.
8. مصرف و هزینه OpenAI، Timeout و Rate Limit مانیتور شود.
